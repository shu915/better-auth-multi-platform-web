  - 全成功なら /profile に移り、一部失敗なら /profile/edit に残る

- Google ログイン(紐づけ・解除を含む)の実装と、自動検証(feature/oauth-google。PR #9 でマージ済み)
  - 設計: マジックリンクで作ったユーザーが root(sub が決まる)。Google は新規登録できず、ログイン済みのユーザーが /profile の「Link Google」で足す任意の手段(自動連携はしない。別メールの Google も可。解除できる)。環境変数 GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET を両方設定したときだけ有効。Go は変えない
  - 方針は src/lib/google-auth-options.ts にあり、src/lib/google-auth.test.ts(7 件)が、本物の Better Auth をメモリ上の DB で動かして守っている(設定を壊すと落ちることを確認済み)
  - 画面の手直し: ボタンのカーソルを pointer にした(globals.css)、エラー文を下に出して画面が動かないようにした(/login と /profile を上寄せ)
  - 実際の Google での手動確認(人間が実施済み: 紐づけ、ログイン、解除、未紐づけ、同じメールの未紐づけ)
  - 検証: tsc・lint・Vitest 84 件・build が通過
  - evaluator は名前では呼べない(このセッションのエージェント一覧にない)ので、general-purpose に evaluator.md を読ませて代役にした。第 1 周: 要修正(中 1、低 2。すべて対応)、第 2 周: 合格。指摘 4(セッションを盗まれた場合、新しいログインなしで Google を紐づけられる)は、その後、人の判断で対策を入れた(下の「セッションを盗まれた場合の対策」)。この対策は、評価者のレビューをまだ受けていない
  - セッションを盗まれた場合の対策(人の判断で追加): (1) 紐づけにも新しいログイン(5 分以内)を要求する(hooks.before、session.freshAge を 5 分に)。(2) 紐づけたら、root のメールに通知する(databaseHooks.account.create.after)。テストは google-auth.test.ts に 6 件追加(古いセッションでは紐づけ・解除できない、入り直せば紐づけられる、通知の宛先と失敗時の挙動)。設定を壊すと落ちることを確認済み(通知の握りつぶしの try/catch だけは、Better Auth 側が元から守っているので、外しても落ちない)
- 退会機能(feat/account-deletion。PR 作成済み): `/profile` の Delete account。他セッション失効 → Go の DELETE /me → Better Auth の deleteUser の順(`src/lib/delete-account.ts`)。Google の紐づけは user と一緒に消える。退会後は root のメールに通知する。`apiRequest` が 204 を扱えるようにした。テスト 17 件追加(101 件)、`deleteUser.enabled` を無効にすると落ちることを確認済み。実機の手動確認は人間が実施済み(退会が通る、Go の profiles と Web の user/account が消える、退会した Google で入れない、同じメールで新規ユーザーになる、5 分超で断られる、Go 停止時はユーザーが残る、退会通知が出る、紐づけ・解除は従来どおり)。evaluator は合格。FRESH_SESSION_SECONDS を 10 分から 5 分にしたので、紐づけ・解除にも効く
- Vitest のテスト(84 件。ロジックと、Google ログインの方針)
- evaluator エージェント(.claude/agents/evaluator.md)と、実装後のループ運用(CLAUDE.md)
- hooks(.claude/settings.json と .claude/hooks/): 実行前のガード、編集ごとの ESLint、応答終了時の tsc・lint・test。evaluator はビルド確認とレビューだけ担当
