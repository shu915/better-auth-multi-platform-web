## 状況: 完了
Web、Go API、モバイル(Expo)、デスクトップ(Tauri)の 4 つで、ひとつのログインを共有する構成が、本番(Vercel + Neon と Render)で動いている。実行中のタスクはない。

## できること(すべて main)
- ログインはマジックリンク(パスワードなし)。/profile で閲覧、/profile/edit で name と bio を保存(bio は Go)
- Google は任意(紐づけ・解除、紐づけ済みのユーザーのログイン。新規登録は不可)。紐づけ・解除・退会は「5 分以内のログイン」を要求し、紐づけると元のメールに通知
- 退会(他のセッションの失効 → Go のデータ → ユーザー → 通知メール)。サーバーだけが呼べる口は HTTP では 403 SERVER_ONLY(/token だけ、Bearer のみのとき例外)
- ネイティブ向けの口(`/api/mobile/*`。デスクトップも使う): /token(JWT)、/exchange(1 回限りのコード + PKCE)、/exchange-state(同じ引き換えを state で。予備)、/profile(name)、/account(退会)
- ブラウザにセッションを置かない戻り: ディープリンクもループバック(`http://127.0.0.1:<port>`、デスクトップの Google)も、コードで渡す
- Google の入口 `/api/auth/expo-authorization-proxy` は、自分の Google アプリの認可 URL だけ通す。ログイン CSRF の防御あり
- 本番向けの守り: DB 接続、レート制限(DB に数える)、CSP(強制)、期限切れの行の掃除(Vercel Cron、毎日 18:00 UTC)
- テスト: Vitest、E2E(Playwright 1 本)、CI(check と e2e)、evaluator と hooks
- 本番デプロイ: Vercel + Neon と Render(シンガポール)。モバイルとデスクトップの実機からも、本番に繋いで確認済み

## 運用メモ
- **Render の DB は 2026-11-08 に期限が切れる**(そのままにする方針)
- デプロイの順: 初回は Go が先、Web が後(Web の退会が Go を呼ぶ)。Go が新しいことを要求し始める変更(例: JWT の auth_time)は、Web が先
- `/api/mobile/*` は Better Auth の外にある。鮮度が要る操作を足すときは、session.createdAt を自分で確認する(docs/design.md)

## 未確認

- セッション盗難対策(紐づけ・解除の 5 分ルールと通知)は、別の目でのレビューをまだ受けていない

## 既知の限界(許容している)
- 独自スキームとループバックの限界: 攻撃者が自分の `cc` を付けたログインメールを被害者に送らせ、被害者の端末で攻撃者のプロセスやアプリが受けると、コードを取られる。Universal Links / App Links が要る。別のアプリが、でたらめな verifier で先に引き換えると、本物のログインは失敗する(セッションは盗まれない)
- `http://127.0.0.1:*` を trustedOrigins に足したので、利用者の Mac のページが信頼された Origin で呼べる。Cookie は SameSite=Lax なので操作はできない(テストで守っている)
- Go API にレート制限がない。/api/mobile/exchange にもない(コードが 256 ビットで当たらないため)。exchange-state は、クライアントごとに 1 分 60 回
- 宛先ごとの制限は、他人のログインを妨害するのに使える(+ のエイリアスは別に数える)
- CSP の退行(静的なページを足すと nonce が付かず止まる)を自動では検知できない
- Cron の DELETE に件数の上限がなく、CRON_SECRET の最小長も強制していない
- 見送ったレビュー指摘: encryptOAuthTokens と storeToken: "hashed"、メール HTML の URL のエスケープ
- Vercel のプレビューのビルドは失敗する(環境変数が Production だけ。使わない方針)
- Render の無料プランはスリープする。スリープ明けの初回は 5 秒で切れて bio が出ないことがある
