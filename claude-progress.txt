## 完了したタスク
ログインとプロフィール
- Better Auth でマジックリンクのログイン(パスワードなし)。JWT は 5 分、payload は最小化。サーバー側の Go 呼び出しは callApi(ブラウザには JWT を出さない)
- /profile(閲覧): email と name はセッション、bio は Go の GET /me/profile。API が落ちていても email と name は出す
- /profile/edit(編集): Server Action updateProfile。name は Better Auth の updateUser、bio は Go の PUT /me/profile。変更したフィールドだけ書き、一部失敗でも成功した分は保存される(再送で直る)。全成功なら /profile に移り、一部失敗なら /profile/edit に残る。検証エラーとレート制限のときも入力値が消えない(submittedValues)
- Google ログイン(紐づけ・解除): マジックリンクで作ったユーザーが root(sub が決まる)。Google は新規登録できず、ログイン済みのユーザーが /profile の「Link Google」で足す任意の手段(自動連携しない、別メールの Google も可、解除できる)。GOOGLE_CLIENT_ID と SECRET を両方設定したときだけ有効。方針は src/lib/google-auth-options.ts。Go は変えない
- セッションを盗まれた場合の対策(人の判断で追加): 紐づけにも新しいログイン(5 分以内)を要求(hooks.before、session.freshAge)。紐づけたら root のメールに通知(databaseHooks.account.create.after)
- 退会(/profile の Delete account): 他セッション失効 → Go の DELETE /me → Better Auth の deleteUser の順(src/lib/delete-account.ts)。確認用メールの入力と、5 分以内のログインが要る。退会後は root のメールに通知(after())。Google の紐づけは user と一緒に消える。apiRequest は 204 を扱う
- サーバーだけが呼べるエンドポイント: /api/auth/delete-user、/update-user、/token、/get-access-token、/refresh-token は HTTP では 403 SERVER_ONLY(Cookie だけで Server Action のルールや JWT の取得を素通りできないように)。Server Action の auth.api.* は通る。/jwks は公開のまま
- 期限切れの行の掃除(Vercel Cron、毎日 18:00 UTC): src/lib/cleanup.ts と src/app/api/cron/cleanup/route.ts と vercel.json。期限切れの verification と session、1 日以上触られていない rate_limit を消す。jwks と user は残す。CRON_SECRET の Bearer と一致しないと何もしない(未設定は 503)

本番向けの守り
- DB 接続(database-config.ts、db.ts): 本番は sslmode=require 以上がないと起動時にエラー(next build の間は検査しない)。プールは globalThis に 1 つ、最大 10 接続(DATABASE_POOL_MAX)、接続待ち 5 秒、query_timeout 10 秒
- レート制限(サインイン用のメールだけ。ログイン不要で押せて、押すたびにメールが送られる唯一の場所): IP ごと(Better Auth、1 分に 5 回)と宛先ごと(src/lib/database-rate-limit.ts、10 分に 3 通、制限されても画面は同じ、DB に届かないときは通す)。どちらも Neon の rate_limit テーブルに数える(原子的な SQL)。本番だけ DB 版、開発とテストはメモリ版
- CSP(src/proxy.ts、src/lib/csp.ts): リクエストごとの nonce、unsafe-inline なし、unsafe-eval は開発だけ、frame-ancestors none。Report-Only で入れ、本番で違反なしを確かめて強制にした(CSP_MODE=enforce)。標準の 404 は静的で nonce が付かず、本番で止められたので、src/app/not-found.tsx で await connection() を呼んで動的にした(本番ビルドを手元で起動して確認済み)
- 本番で拒否するもの: EMAIL_TRANSPORT の console と file(リンクがログやディスクに残るため)、http の API_BASE_URL

テストと開発の仕組み
- Vitest(約 190 件): ロジック、Google ログインの方針(メモリ上の Better Auth)、Server Action の結線、実 Postgres(マイグレーションを専用スキーマに流して外部キー、一意制約、jwks、退会、レート制限、Cron の削除)、本物の HTTP サーバーに対する apiRequest。守りたい設定を壊すと落ちることを、そのつど確認済み。画面のテストは入れない方針
- E2E(Playwright。e2e/account-flow.spec.ts): ログイン → 編集 → 退会を、本物のブラウザ、Web、Go、Postgres で通す 1 本。e2e/prepare.mjs が DB を作り直し、Go と Web を別ポート(8180、3100)で起動。メールは EMAIL_TRANSPORT=file で書き出して読む。開発サーバーで動くので、本番ビルドだけの挙動は通らない。本物の Google は含めない
- CI(GitHub Actions): check(lint、テスト、型、ビルド)と e2e の 2 ジョブ。DB を使うテストが SKIP されると失敗にする
- evaluator エージェント(.claude/agents/evaluator.md)と、実装後のループ運用(CLAUDE.md)。hooks(.claude/settings.json と .claude/hooks/): 実行前のガード、編集ごとの ESLint、応答終了時の tsc・lint・test
- npm の不具合: npm install が package-lock から @rolldown/binding-* を消すので、一時フォルダで lock を生成して取り込む(CLAUDE.md の「依存を足すときの注意」)

## 既知の限界(許容している)
- Go API にレート制限がない。JWT は退会後も最大 5 分有効で、その間の PUT /me/profile が行を作り直す
- 宛先ごとの制限は、他人のログインを妨害するのに使える(10 分に 3 通。+ のエイリアスは別に数える)
- CSP の退行(静的なページを足すと nonce が付かず止まる)を自動では検知できない。E2E は開発サーバーで動く。report-to もない。静的なページを足したら、本番ビルドを手元で起動して HTML の nonce を確かめる(CLAUDE.md)
- Cron の DELETE に件数の上限がなく、CRON_SECRET の最小長も強制していない(今の規模では問題なし)
- 見送ったレビュー指摘: encryptOAuthTokens と storeToken: "hashed"(Better Auth の既定値が未確認で、既存データの移行も要る)、メール HTML の URL のエスケープ(Better Auth が組み立てる)
- Vercel のプレビューのビルドは失敗する(環境変数を Production だけに入れたため。使わない方針)
- 無料プランの Render はスリープする。Web の Go 呼び出しは 5 秒で切れるので、スリープ明けの初回に bio が出ないことがある
